## Deployment

Apply `prisma migrate deploy` before deploying the code. Migration `20261128100000_qa_inventory_and_recorded_checks` adds four nullable bike check fields and the `payment_review` order status. Existing stock receives no fabricated HPI or inspection claims.

Payment-review orders appear under Active and Payment review in Sales. Staff must resolve/refund the actual provider payment before recording its refund in the DMS. These orders do not allocate stock.

## Validation

- `npm test`: 15 tests, including six new regression tests.
- `npm run typecheck`, `npm run lint`, `npm run build`.
- 68 browser scenarios using disposable local customer, stock and order fixtures.
- Five transaction checks exercise actual checkout code against the local database, including concurrent purchases and duplicate/late payment callbacks. Only Next request-bound cache wrappers are replaced in that standalone runner.
- Real payment, mail and vehicle-provider calls are not simulated as successful production integrations.

## Configuration still needed

- Stripe secret and webhook secret for real payments.
- Resend API key and verified `MAIL_FROM` for verification, password reset and enquiry/order emails. Customer record access requires email verification; staff login is separate.
- Vercel Blob token for staff product/media uploads. Private enquiry-photo storage uses the existing Supabase integration.
- A selected vehicle-data provider and credentials for registration/specification lookup. Paid cap hpi reports are a separate integration requiring its own account and API agreement.
- Client-approved legal/business/provider information and workshop pricing. Existing draft content must not be presented as approved.

No real payments, customer messages or purchased vehicle reports were created during regression testing.
